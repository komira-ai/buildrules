# tools/scrub: the check that runs before anything is pushed to a public repository

    buck2 build //tools/scrub:scrub          # red when anything below is found; the output is the report

It reads every tracked file (each package ends with `scrub_files()`, which names the package's own files; the root package also names the
dotfiles a glob does not return) and fails on:

- a date before 2026-09-01 in any spelling (ISO, compact, month names, the two bare years before 2026);
- a person's name, an email address, a home path, a host of a private network, an IPv4 address (loopback and the documentation ranges
  excepted), a remote-execution endpoint;
- the vocabulary of a private control plane, and the name of the project this repository grew out of, except in the two public
  repository paths this repository and the mopm releases live at.

Two things that are not ours are reported as `allowed (<reason>)` and counted at the end of the report, never hidden: the Rust edition
(`edition = "2024"` is the name of a language edition, not a date) and an author's address inside the metadata of an npm package in a lock file.
They, and the one maintainer address of the .deb packages (`why_maintainer`, a no-reply address of the code host, in `packaging/deb/control`), are the only allowances (`upstreamReason` and the email scan in scrub.zig). The release date of a pinned artifact is not one: pins use versioned URLs.

`--require` names files that must be among the inputs: a package whose `scrub_files()` is missing, or a glob that came up empty, is red and
not green. A new package needs `scrub_files()` at the end of its BUCK file and its label in `tools/scrub/BUCK`. The one package without it is
`examples/crates/third_party/buildrules`, whose BUCK file is generated by `buildrules sync` (`crates//:sync_check` keeps it as generated).

The banned words are spelled in parts in scrub.zig and scrub_test.zig, so the tool does not report itself.
